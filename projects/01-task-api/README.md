# Task API

当前主项目：使用 Go 标准库手写个人任务管理 HTTP API。

## 当前可运行内容

- `GET /health` 返回 `200` 和 JSON 健康状态。
- 其他方法访问 `/health` 返回 `405`。
- 已定义 Task 数据模型，尚未实现任务 CRUD。

启动：

```powershell
go run ./projects/01-task-api
```

测试：

```powershell
go test ./projects/01-task-api
```

## 手写里程碑

### 1. 内存存储

实现任务的新增、按 ID 查询和列表查询，数据只保存在内存中。

完成条件：能用测试证明 ID 唯一；查询不存在的任务会返回可判断的错误；存储不依赖 HTTP。

### 2. 创建和查询 API

实现 `POST /tasks`、`GET /tasks` 和 `GET /tasks/{id}`。

完成条件：请求和响应是合法 JSON；标题去掉首尾空白后不能为空；创建时未提供状态则默认使用 `todo`，提供非法状态则返回 `400`；创建返回 `201`；不存在返回 `404`；错误方法返回 `405`。

### 3. 修改和删除 API

实现 `PATCH /tasks/{id}` 和 `DELETE /tasks/{id}`，状态只允许 `todo`、`doing`、`done`。

完成条件：未提供的字段保持原值，明确提供的空标题和非法状态被拒绝；修改会更新 `updated_at`；删除成功返回 `204`；不存在返回 `404`。

### 4. 测试和整理

为存储、校验和 HTTP Handler 编写表驱动测试，并只在职责确实分开时拆文件。

完成条件：正常与错误路径都有测试；`go test ./...` 和 `go vet ./...` 通过；没有为了“以后可能用到”而创建接口或分层。

### 5. 并发安全

用并发测试暴露共享 Map 的数据竞争，再使用合适的同步方式修复。

完成条件：能解释锁保护的数据和范围；`go test -race ./...` 不报告数据竞争。

### 6. JSON 文件持久化

启动时读取任务文件，任务变化后安全写回；处理文件不存在、内容损坏和写入失败。

完成条件：重启后数据仍存在；写入过程不会轻易破坏原文件；持久化失败会返回明确错误，并且本次内存修改不生效。

### 7. 工程化

加入端口和数据路径配置、HTTP Server 超时、结构化日志及优雅退出。

完成条件：端口可通过环境变量修改；收到终止信号时停止接收请求并等待已有请求结束；README 包含完整运行和调用示例。
