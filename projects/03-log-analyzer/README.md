# 日志分析器

目标：从文本文件读取访问日志，解析为结构化记录并生成统计报告，练习文件处理、字符串解析、错误分类和性能分析。

## 输入约定

第一版每行包含五个以空格分隔的字段：RFC3339 时间、HTTP 方法、路径、状态码和耗时毫秒数，例如 `2026-08-17T10:00:00Z GET /tasks 200 12`。先在测试中固定几个合法与非法样例，再实现解析器。

## 递进需求

1. 逐行读取日志文件并解析记录。
2. 统计总请求数、各状态码数量、访问次数最多的路径和平均耗时。
3. 对坏行记录行号和原因，继续分析剩余内容。
4. 支持把报告输出为终端文本或 JSON；JSON 至少包含 `total_requests`、`status_counts`、`top_path`、`average_duration_ms` 和 `invalid_lines`。
5. 使用基准测试测量大文件处理，再决定是否引入并发解析。
6. 如果并发确实更快，加入固定 Worker Pool，并保证最终统计没有数据竞争。

## 完成条件

- 空文件、合法文件和包含坏行的文件都有自动化测试。
- 统计结果可由小型手算样例验证，坏行不会污染正确记录。
- 没有合法记录时，总请求数、平均耗时和坏行数仍正常输出，`top_path` 为 `""`；多个路径并列第一时选择字典序最小的路径。
- 读取大文件时按行处理，不要求把整个文件一次载入内存。
- 在基准数据证明有收益前，不为了使用 goroutine 强行并发。
- `go test ./...`、`go vet ./...` 和需要并发时的 `go test -race ./...` 通过。

并发网址检测器完成后再开始本项目；当前不要创建实现文件。
